# 小程序包体瘦身：全量压缩本地图片

## 背景与目标

- 现状：`miniapp/dist` 约 3.0MB，超过微信主包 2MB 上限（预览/上传报错即"编译不通过"的原因）。其中图片 2.26MB（57 张，54 张 PNG）是绝对大头，代码仅约 0.7MB。
- **目标**：主包降到 **≤1.9MB**（留余量），开发者工具可正常预览。
- **非目标**：不做分包；不迁移资源到 COS（若压缩后实测仍超 2MB，停下来单独向你提 CDN 化子方案）；不改业务逻辑与页面布局；不动 `public/` 塔罗资源与 `check-assets` 体系（`miniapp/src/assets` 不在其检查范围）。

## 前置条件

你已确认会**先自行提交当前工作树约 40 个文件的未提交改动**。我开始前会检查 `git status`；若仍有未提交改动，先列出并等你处理，避免两批改动混在同一提交里。

## 实施步骤

1. **写一次性压缩脚本** `scripts/optimize-miniapp-assets.mjs`（用 sharp，npx 运行，不入依赖）：
   - 扫描 `miniapp/src/assets/`：PNG >16KB 转 WebP（q80、保留 alpha）；小 PNG 调色板优化；JPG 转 WebP；已有 WebP 过大者重压。
   - 先 **dry-run 输出前后体积预估报告**，确认预估达标后再落盘替换（删除被替换的旧文件）。
2. **更新引用**：用 `rg` 找出所有被转换文件的引用（`require`/`import`/scss `url()`，预期涉及 `launchAssetLoader.ts`、`XiaoduoliBoxScene.tsx`、`JournalEditorForm.tsx` 及若干 scss），改后缀为 `.webp`。Taro/webpack 已有 `.webp` 处理先例（room-background.webp），无需改构建配置。
3. **清缓存重建**：删 `miniapp/dist` → 带 `TARO_TAROT_ASSET_BASE_URL`（沿用现有生产 COS 版本地址）→ `npm run build:weapp`。
4. **实测包体**：统计 dist 总量与 assets 构成、最大文件清单。达标线 ≤1.9MB；不达标则调参重压（q75、必要时超大图缩尺寸），仍不达标即停下向你提 CDN 化方案。
5. **验证**：跑 miniapp 的 tsc 类型检查 + 单测（最快相关检查）。
6. **文档同步**：更新 `docs/features/miniapp.md` 的本地资源清单表（大小/格式变化）。
7. **预览验收**：按 `.agents/rules/miniapp-change.md` 清开发者工具缓存重开预览（cli close + cli auto），**画质需你验收**——视觉变化按规则须你接受后才能合并/部署。
8. **提交**：仅 stage 本任务路径（assets、引用代码、脚本、文档），中文 commit（如 `小程序: 压缩本地图片转 WebP 降低主包体积`）。

## 风险

- WebP 压缩有画质损失，需你预览验收（alpha 透明图通常保真良好）。
- scss `url()` 引用需全量排查，避免漏改导致构建失败（构建会直接暴露）。
