# 喂食道具选择气泡 + 统一改名「牛奶」+ 台词修正

## 交互设计（已确认的决策）

- 点「喂食」**永远先弹气泡**（哪怕只剩一种），另一种以置灰态列出，绝不在不知情时消耗稀缺骨头；两者都为 0 时维持现有置灰+toast 兜底。
- 气泡锚在喂食按钮正上方（`.pet-action-button` 已是 relative，`bottom:100%` 上浮，`.pet-actions-panel` 无 overflow 裁剪）：两张横排选项卡——道具图标（复用 `item-dog_food-v6.png`/`item-bone-v6.png`，前者本就是奶瓶图）+ 名称（牛奶/骨头）+ `×库存`；库存 0 的选项 grayscale 置灰不可点。
- 点按遮罩关闭：气泡打开时渲染一层透明 fixed 全屏遮罩（onClick 关闭，仿 MiniappModal backdrop 先例，仓库无 catchTap 惯例）；遮罩 z-index 6、气泡 7，可压住场景卡内 z 2~3 浮层，不盖 TabBar 与 z≥40 的模态。
- 轻动效：淡入+上浮（opacity 0→1 / translateY 10px→0 / scale .92→1，transform-origin bottom left，.22s cubic-bezier(.22,1,.36,1) both），按仓库惯例加 `prefers-reduced-motion` 关动画；选项按压态 `scale(.94)+brightness(.95)`（hoverClass 惯例）。
- 选中 → 关气泡 → `onAction('feed', itemId)`；气泡打开瞬间**重新拉一次库存**（GM 模式跳过），保证弹层里的计数是最新的。

## 服务端（server/）

1. `domain/itemCatalog.ts`：`ITEM_CATALOG.dog_food.name` 改「牛奶」；新增 `FEED_ITEM_IDS: readonly ItemId[] = ['dog_food','bone']`（`ACTION_COST.feed='dog_food'` 保留作缺省回退）。
2. `services/nestTaskService.ts` `consumeForAction` 加第 4 参 `itemId?`：消耗 `itemId ?? ACTION_COST[action]`；feed 时 itemId 必须在 FEED_ITEM_IDS 内、非 feed 动作不接受 itemId（越权即抛错，路由层 zod 之外的第二道防线）；继续返回实际消耗的道具 id。
3. `http/roomRoutes.ts` pet-actions：body schema 扩为 `{ action: enum, itemId: z.enum(['dog_food','bone']).optional() }` + refine（非 feed 带 itemId → 400）；接住 `consumeForAction` 返回值传入 `pets.applyAction`。
4. `services/petService.ts`：`applyAction` 加 `consumedItemId?` 参数，并入 `PetActionOutcome`。
5. `services/petBrain.ts` 喂食感谢台词按 `outcome.consumedItemId` 分桶（台词修正）：
   - 牛奶桶：`汪！${actor}喂的牛奶最香了，肚子圆滚滚～`、`咕嘟咕嘟！${actor}的牛奶是全世界最好喝的！`、`吃饱饱！${actor}最好了，蹭蹭～`
   - 骨头桶：`呜哇谢谢${actor}！骨头味道我给满分！`、`咔嚓咔嚓，这根骨头我要慢慢啃～`、`吃饱饱！${actor}最好了，蹭蹭～`
   - 数值零改动（petRules 不动）：喂骨头=喂牛奶=饱食+30/心情+5/亲密+2/经验+5。
