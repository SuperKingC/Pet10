# UI Presentation Rules

## Scope

本规则适用于 Pet10 微信小程序，约束页面、功能入口和页面级覆盖层使用哪一种界面容器。

页面级界面只允许以下三种形式：

1. **整页（full screen）**：替换当前主要内容，适合主导航页面或需要持续专注的完整流程，并提供明确的返回路径。
2. **弹窗（modal/dialog）**：覆盖在当前页面之上，带遮罩和明确的关闭方式；移动端可以接近全屏，但不得贴住屏幕底边并以抽屉方式滑入。
3. **下拉栏（drawer/sheet）**：从屏幕顶部或底部边缘滑出的页面级抽屉，包括代码或设计中称为 `drawer`、`sheet`、`bottom sheet`、上拉栏或下拉栏的形式。

普通表单控件不属于页面级界面容器，例如原生日期选择器、性别选择器和 `select` 下拉选项可以按控件语义使用。

## Required Decisions

- 下拉栏只允许用于点击主页底部导航中央狗脚印后打开的快捷入口栏。
- MBTI 测试固定使用弹窗，不得使用下拉栏。
- “联系我们”固定使用弹窗，不得使用下拉栏。
- 除狗脚印快捷入口栏外，其他页面级界面必须在整页和弹窗之间选择，不得新增或沿用下拉栏形式。
- CSS 类名或组件名中出现 `sheet`、`drawer` 或 `modal` 不能替代对实际呈现方式的判断；以用户看到的布局、定位和进入方式为准。

## Decision Guide

- 主导航目标、独立功能、长流程或需要稳定返回栈的内容优先使用整页。
- 在当前上下文中查看补充信息、完成短操作、确认结果或编辑少量内容时使用弹窗。
- 不得为了减少开发量，把本应使用整页或弹窗的内容临时改成下拉栏。
- 如果无法确定应使用整页还是弹窗，修改代码前先向用户确认；不得自行新增第四种页面级呈现形式。

## Existing Interfaces

- 现有实现即使使用了非狗脚印下拉栏，也不能作为后续设计先例。
- 新增或修改页面级界面时必须遵守本规则。
- 如果本次需求会触及一个不符合本规则的旧界面，应把容器迁移纳入同一需求；如果迁移会明显扩大范围，先向用户确认拆分方案。

## Review Checklist

- [ ] 页面级界面已明确归类为整页、弹窗或狗脚印下拉栏。
- [ ] 只有主页狗脚印使用下拉栏。
- [ ] MBTI 和“联系我们”使用弹窗。
- [ ] 弹窗具有遮罩、关闭方式、键盘与返回操作的合理处理。
- [ ] 整页具有明确的进入和返回路径。
- [ ] 不确定的容器选择已经过用户确认。

## Visual Design Quality

- 用户要求「更好看 / 重新设计 / 优化界面」时，方案必须把**动画编排与图片资源**纳入考虑并主动提案，不得默认只做 CSS 颜色/间距微调后交差。
- 新增图片资源必须遵守 `.agents/rules/miniapp-image.md`（PNG8/JPEG、禁本地 WebP、优化脚本与 TinyPNG 流程）与主包 2MB 预算；装饰性插画优先用 `miniapp/tools/` 的 SVG→sharp 生成脚本出件（体积可控、风格统一），AI 生图素材按 source-only 入 `design-assets/`。
- 动效必须提供 `prefers-reduced-motion` 降级，且不阻塞交互。
- 视觉结果经用户验收前不得合并或部署（既有门槛不变）。
