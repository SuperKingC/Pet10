# 聊天详情页底部导航显示规则设计

## 背景

当前主应用由 `src/components/AppShell.tsx` 常驻挂载四个主标签页，并在壳层末尾统一渲染 `src/components/TabBar.tsx`。进入某个会话后，`ChatView` 以全屏层显示，但底部导航仍由应用壳渲染。

## 目标

用户进入某个具体会话的聊天详情后，底部导航完全隐藏；点击聊天详情的返回按钮回到会话列表后，底部导航立即恢复。

## 非目标

- 不隐藏会话列表页的底部导航。
- 不改变“小窝”“小记”“我的”等其他主标签页的底部导航。
- 不修改聊天消息、发送、上传、实时连接、未读计数或会话状态持久化逻辑。
- 不修改底部导航的样式、图标、顺序或交互。
- 不改变当前工作区已有的静态资源和 COS 加载调整。

## 设计

显示规则由拥有页面状态的 `AppShell` 决定，不把页面级规则下沉到通用 `TabBar` 组件。

- 当 `activeTab` 为 `messages` 且 `currentRoomId` 存在时，表示聊天详情已打开，`AppShell` 不渲染 `TabBar`。
- 当聊天详情的返回操作清空 `currentRoomId` 后，`AppShell` 重新渲染 `TabBar`。
- 会话列表的 `currentRoomId` 为空，因此继续显示底部导航。
- 其他主标签页继续显示底部导航，即使会话 ID 被保存在会话状态中也不会受影响。

条件渲染会把底部导航同时从视觉界面、点击区域和辅助功能树中移除，避免仅用 CSS 隐藏产生不可见交互区域。

## 代码范围

- `src/components/AppShell.tsx`：根据当前标签页和会话详情状态条件渲染 `TabBar`。
- 聚焦测试：覆盖会话列表显示、聊天详情隐藏、返回列表恢复显示的状态规则。
- `docs/features/app-navigation.md`：记录聊天详情页的底部导航规则和验收项。

## 验证

1. 先运行聚焦测试并确认新增断言因现有行为而失败。
2. 完成最小实现后重新运行聚焦测试，并执行前端类型检查或项目快速验证。
3. 运行 `npm run check:docs`，确认导航文档有效。
4. 启动 `npm run review`，在浏览器中从消息列表进入任一会话，确认底部导航隐藏；点击返回，确认底部导航恢复。

## 风险与回退

主要风险是隐藏条件过宽，导致会话列表或其他主标签页也失去底部导航。聚焦测试将明确区分这三种状态。回退时删除 `AppShell` 的条件渲染并撤销对应测试和文档条目即可。

## 验收标准

- 会话列表显示底部导航。
- 打开任一聊天详情后，底部导航不存在且不会占用点击区域。
- 从聊天详情返回会话列表后，底部导航立即恢复。
- “小窝”“小记”“我的”页面的导航行为保持不变。
