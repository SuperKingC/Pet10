# 图片生成诊断与参考图输入设计

## 背景

图片生成上游可能以 HTTP 200 返回包含 `error` 的 JSON。现有服务只按图片结果结构解析，导致此类失败被折叠为泛化的 503，页面无法显示上游错误码或生成耗时。参考图目前只能通过文件选择器添加。

## 目标

1. 为图片生成成功与失败提供可见的耗时信息。
2. 解析并安全地暴露上游错误码和请求 ID，便于用户与运维定位问题。
3. 在服务端记录脱敏的上游错误诊断信息。
4. 支持向图片描述区域粘贴图片，以及向参考图添加区域拖拽图片。

## 非目标

- 不替换图片模型、上游供应商、邀请码或限流规则。
- 不改变每张 2 MB、最多两张参考图的限制。
- 不添加自动重试。
- 不向浏览器或日志公开 API Key、提示词原文、参考图片数据或完整上游响应。

## 服务端契约

### 上游响应处理

图片生成服务在读取上游 JSON 后，先检查顶层 `error`。

- 上游响应包含 `error` 时，提取安全字段：错误码和请求 ID。
- 错误码优先取 `error.code`；若不存在，使用上游 HTTP 状态；均不可用时不提供错误码。
- 请求 ID 仅从上游响应体中受支持字段提取；不透传完整错误消息。
- 未包含 `error` 时，按既有图片结果结构解析。

### Pet10 API 响应

所有生成响应添加 `durationMs`。

失败响应保留已有 `error` 字段，并可包含：

```json
{
  "error": "image_generation_unavailable",
  "durationMs": 18432,
  "upstreamCode": 502,
  "requestId": "req_example"
}
```

- 上游明确拒绝（非 5xx）映射为 HTTP 502。
- 上游错误码为 5xx、网络异常或响应结构无效映射为 HTTP 503。
- 邀请码、限流与输入校验保持现有状态码和错误值。

### 日志

图片路由在失败时记录单行结构化信息：Pet10 HTTP 状态、稳定错误值、上游错误码、请求 ID、耗时。日志禁止包含 Key、提示词、参考图或完整上游响应。

## 前端行为

### 结果与错误

- 成功：显示“生成完成，耗时 X.X 秒”。
- 失败：显示“图片服务失败（错误码 N），耗时 X.X 秒”。无上游错误码时显示通用失败文本和耗时。
- 有请求 ID 时在错误信息中显示，供用户提交给供应商。
- 保留邀请码、限流和参考图本地校验的现有清晰提示。

### 粘贴参考图

- 用户在图片描述输入框中粘贴时，若剪贴板包含图片文件，优先添加图片为参考图并阻止文本粘贴。
- 无图片时保持浏览器默认文本粘贴行为。
- 添加过程复用既有格式、压缩、单张 2 MB 和最多两张校验。

### 拖拽参考图

- 参考图片区域可接收包含图片文件的拖入。
- 拖入期间显示高亮状态。
- 放下图片后复用既有添加与校验逻辑。
- 非图片拖入或超过数量限制显示明确提示；默认浏览器文件打开行为被阻止。

## 测试与验收

- 服务端：覆盖 HTTP 200 内嵌上游错误、上游 5xx、成功图片结果、诊断字段和日志脱敏输入。
- 前端：覆盖生成耗时/错误诊断文本、描述框粘贴图片、正常文本粘贴、参考图区域拖拽和拖拽高亮。
- 人工验收：启动 `npm run review`，访问本地 `/image`，检查成功/失败提示、拖拽和粘贴反馈，以及浏览器控制台无错误。
