# 共享邀请码生图房间设计

## 目标

在现有 Vite + React 前端和 Node/TypeScript 服务端中增加一个可分享的生图页面。好友通过公开链接打开页面，输入所有人共用的邀请码、填写提示词并生成图片。真实上游 API Key 只保存在服务端环境变量中，浏览器永远不会收到该 Key。

## 已确认范围

- 使用现有项目的前端和 Node 服务端，不新增 Cloudflare Worker。
- 访问控制使用一个共享邀请码；邀请码由服务端环境变量配置。
- 基础限流：每个客户端 IP 每分钟最多 3 次，每日总计最多 30 次；阈值可通过环境变量调整。
- 上游固定为 `https://apirouter.zhiqiteai.cn/ApiRouterServ/v1/chat/completions`，使用 `openai/gpt-5.4-image-2` 的图片模态。
- 页面首屏即为工具，不做营销落地页。
- 默认每次生成 1 张图片，提示词最多 4000 字符，模型和尺寸使用白名单。

## 用户流程

1. 好友打开 `/image`。
2. 输入共享邀请码；邀请码只提交给同源服务端接口。
3. 填写提示词，选择允许的尺寸和模型。
4. 点击生成，页面显示加载状态并防止重复提交。
5. 成功后展示图片预览、生成信息和下载按钮；失败时显示不泄露内部细节的可读错误。

## 系统架构

### 前端

新增生图页面和局部组件，负责表单状态、客户端校验、请求状态、错误展示及图片结果渲染。前端请求同源 `POST /api/images/generations`，不读取或保存上游 API Key。邀请码仅保存在当前页面状态或浏览器会话存储中，不写入 URL。

### 服务端

新增图片路由和代理服务：

- 从 `Authorization: Bearer <invite-code>` 或请求体约定字段读取邀请码，并与服务端环境变量常量时间比较。
- 从可信代理头解析客户端 IP，部署配置不可信时回退到 socket 地址；避免任意请求头导致所有用户共享限额。
- 执行每 IP 每分钟和每日计数。计数存储复用项目已有持久化能力；若当前部署没有持久化计数器，先使用进程内实现并明确其多实例局限，生产部署要求单实例或后续接入 Redis/数据库。
- 校验 JSON 请求体、提示词长度、模型、尺寸和 `n` 参数。
- 固定拼接上游路径 `/chat/completions`，禁止客户端提供 URL、路径或自定义上游 Authorization。
- 使用服务端 `UPSTREAM_API_KEY` 调用上游，透传必要的 JSON 响应，不透传上游敏感响应头。
- 对上游错误、超时和非 JSON 响应做统一映射，响应中不得出现真实 Key、环境变量值或内部堆栈。

接口：

```text
POST /api/images/generations
Authorization: Bearer <shared-invite-code>
Content-Type: application/json

{
  "prompt": "...",
  "model": "<allowed-model>",
  "size": "1024x1024",
  "n": 1
}
```

成功响应尽量保持 OpenAI 兼容图片响应结构，便于前端和未来客户端复用。服务端对上游返回的图片 URL 或 base64 数据均支持展示；下载按钮在浏览器允许时直接下载，否则打开图片地址。

## 配置

在 `.env.example` 中增加：

```env
IMAGE_INVITE_CODE=change-me
IMAGE_UPSTREAM_BASE_URL=https://apirouter.zhiqiteai.cn/ApiRouterServ/v1
IMAGE_UPSTREAM_API_KEY=
IMAGE_RATE_LIMIT_PER_MINUTE=3
IMAGE_DAILY_LIMIT=30
IMAGE_MAX_PROMPT_LENGTH=4000
```

真实值只写入部署环境，不提交仓库。上游模型白名单和尺寸白名单固定在服务端代码或安全配置中，避免好友传入高成本参数。

## 安全与隐私

- 仅允许 HTTPS 部署。
- 错误邀请码返回 401，限流返回 429；不区分“邀请码不存在”和“邀请码错误”的细节。
- CORS 默认限制为同源；若部署前后端不同域名，使用显式允许域名，不使用通配符。
- 请求日志仅记录时间、哈希后的 IP、状态码和耗时，不记录真实 Key；提示词默认不长期保存。
- 设置上游账户余额/消费上限，因为代理不能替代上游费用保护。
- 共享邀请码一旦泄露，所有人都会受到影响；通过修改环境变量并重启/重新部署实现轮换。

## 验收标准

- 未输入邀请码或邀请码错误时不能调用上游。
- 浏览器网络请求和静态资源中不存在 `IMAGE_UPSTREAM_API_KEY` 的值。
- 合法请求可以生成并显示至少一种上游返回格式的图片。
- 同一 IP 第 4 次/分钟请求被拒绝；超过每日总量请求被拒绝；配置可调整。
- 非白名单模型、尺寸、`n > 1`、超长提示词和超大请求体被拒绝。
- 上游超时、4xx、5xx 时页面显示可读错误且服务端不泄露内部信息。
- 前端测试覆盖表单提交、加载/失败/成功状态；服务端测试覆盖认证、参数校验、限流和上游错误映射。

## 未包含内容

- 多用户账号系统、个人额度面板、历史图片持久化。
- 管理员网页控制台。
- 任意模型或任意 OpenAI API 代理。
- 图片内容审核；如需要，应在后续单独设计。
