# 塔罗选牌飞行动画设计

## 目标

只重做 `fan` 阶段点击卡牌后飞入已选区的动画，使卡牌从扇面起点到目标槽位的运动连续、平滑且准确。

## 非目标

- 不修改选牌数量、重复点击锁和阶段状态机。
- 不修改扇形展开、翻牌、洗牌、切牌或阅读阶段。
- 不修改卡牌图片与其他运行时资源。
- 不引入第三方动画库。

## 现状问题

当前动画直接覆盖扇形卡牌按钮已有的 `transform`。动画开始时，卡牌会从扇形旋转与偏移姿态切换到另一套关键帧；动画结束时，原卡立即进入隐藏状态，同时已选槽位立即出现。这两个交接点都会造成视觉顿挫。

## 方案

点击卡牌时：

1. 读取卡牌视觉元素的视口矩形。
2. 根据当前已选数量定位对应的目标槽位。
3. 创建一个独立、固定定位的飞行视觉副本。
4. 原扇形卡牌保持原布局，只在副本起飞后淡出。
5. 副本使用 Web Animations API 从真实起点飞向真实目标：
   - `0%`：保持原卡尺寸、位置和扇形角度。
   - `24%`：轻微上抬和放大，脱离扇面层级。
   - `72%`：沿弧线接近目标，并逐渐校正旋转。
   - `100%`：与目标槽位尺寸、位置和角度完全一致。
6. 动画完成后只触发一次 `finish-pick`，移除副本，并显示已选槽位。

## 华丽版动画契约

- 总时长：`900ms`。
- 已选牌整行向下微调约 `8px`，通过重新分配上下外边距保持页面总占位不变。
- 缓动：`cubic-bezier(.22, .78, .2, 1)`。
- `0–140ms`：边缘流光蓄能，紫色能量尾迹和前后景粒子开始出现。
- `140–600ms`：两层粒子以不同速度移动，牌后形成紫色拖尾，金色流光扫过牌背。
- 副本只显示卡牌本体，不创建拖尾、粒子、扫光、光环或落位爆发。
- 前半段快速完成约八成位移，后半段持续减速并收束旋转和尺寸。
- 飞行期间保持卡牌亮度稳定，仅平滑过渡边框和阴影。
- 飞行副本最后一帧的边框、阴影、亮度、尺寸和位置与真实已选牌完全一致。
- 真实已选牌不再承担额外亮度动画，避免 DOM 交接时重新变亮。
- 同一时间只允许一张牌飞行。
- 动画取消或组件卸载时不提交完成事件。
- `prefers-reduced-motion` 保持现有逻辑：直接完成选牌，不创建飞行副本。

## 已选区

- 删除“已选 a/b”上方的装饰性小牌堆。
- 已选槽位和计数位置保持不变，不增加新的永久装饰。

## 响应式策略

起点与终点均从 DOM 实际坐标计算，不依赖固定像素位移，因此移动端 `390x844` 与桌面端 `1280x800` 使用同一动画逻辑。

## 验收

- 点击瞬间没有姿态跳变。
- 飞行中段没有停顿或突然变向。
- 卡牌落位时不闪烁、不重影。
- 飞行中只出现卡牌本体，不出现粒子或附加光效。
- 飞行节奏明显先快后慢，副本与真实已选牌切换时亮度不变。
- “已选 a/b”上方不再显示小牌堆。
- 快速重复点击不会同时飞出多张牌。
- 移动端和桌面端都准确落入对应槽位。
- reduced motion 直接得到正确已选结果。

## 2026-08-11 已选牌尺寸调整

- 上方已选牌必须明显大于下方扇形牌。
- 上方已选牌使用响应式尺寸：桌面最大约 `78×122px`，窄屏最小约 `62×98px`。
- 下方扇形牌缩小为桌面约 `58×92px`，`380px` 以下约 `52×82px`。
- 三张模式保持居中，并使用约 `20–28px` 的舒展牌间距。
- 五张模式在 `390px` 宽度内直接单行容纳；`380px` 以下缩小为约 `52×82px` 并保留约 `3px` 正间距，不允许相邻牌重叠。
- 飞行副本继续读取真实起点和槽位尺寸，因此飞行过程中自然从较小扇形牌放大到较大已选牌。
- 不修改 `900ms` 时长、先快后慢节奏、选牌数量、交互锁或其他塔罗阶段。
