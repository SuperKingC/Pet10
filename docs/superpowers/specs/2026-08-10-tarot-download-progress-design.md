# 塔罗资源下载进度与速度优化设计

## 目标

让塔罗资源下载进度反映实际接收量，并在正常宽带、服务器健康且无缓存的条件下，争取将 24 个运行时资源（约 4.88 MiB）控制在 10 秒内完成。

## 非目标

- 不修改塔罗玩法、阶段状态机或动画时序。
- 不替换图片、不降低图片质量。
- 不加载 `source-only` 概念图。
- 不通过虚增百分比或提前进入塔罗来伪造速度。
- 不调整生产部署拓扑。

## 方案

### 进度计算

- `imageResourceLoader` 在有 `Content-Length` 时继续报告精确字节进度。
- 没有 `Content-Length` 时报告已接收字节和实际已完成字节；预加载器使用当前已知总量加未知资源的平滑估算，避免按文件完成数从 8% 跳跃。
- 图片下载完成后仍等待解码成功，再标记资源完成。
- 进度始终限制在 0 到 1，最终完成时强制报告 1。

### 下载并发

- 默认并发数从 3 提高到 6。
- 通过现有 `concurrency` 参数保留测试和未来调优能力。
- 不增加资源数量，避免额外网络请求。

### 重复打开

- 保留浏览器 HTTP 缓存作为重复进入时的第一层复用。
- 本次不新增应用级 Blob 缓存，避免引入生命周期和内存回收复杂度。

## 验收

- 聚焦测试覆盖：无 `Content-Length` 的流式响应持续推进；默认并发为 6；已有并发配置仍生效。
- `npm test -- --run src/games/tarot/tarotAssets.test.ts src/games/tarot/tarotDownloadStatus.test.ts` 通过。
- `npm run build` 通过。
- `npm run review` 启动后，在塔罗入口检查进度连续性、网络请求数、控制台错误和移动/桌面布局。
- 10 秒目标仅适用于上述正常网络条件；慢速、丢包、服务器故障或禁用缓存时不作绝对保证。
