# 塔罗仪式动效重设计规格

## 目标

在现有塔罗流程中重做洗牌、切牌和抽牌动效，采用已确认的 B「紫雾回响」视觉方向：牌的运动范围明显扩大，但速度和旋转保持克制；玄幻感来自紫色呼吸雾光、柔和金色高光和多层牌影。动效必须让用户清楚看到牌的来源、去向和当前操作是否已完成。

本次只调整动效表现、交互锁定和相关布局，不改变牌库、牌阵数量、随机抽牌规则、翻牌结果或解读内容。

## 现有上下文

- `src/games/tarot/TarotGame.tsx` 负责 `shuffle`、`cut`、`fan` 三个阶段的状态和事件。
- `src/styles.css` 已提供牌背、洗牌牌组、切牌牌叠、扇形选牌和已选牌区域的样式，但存在多组后置覆盖关键帧，导致同一元素的轨迹不容易预测。
- `src/games/tarot/tarotRitualStyles.test.ts` 通过读取 CSS/TSX 检查仪式结构和关键动效约束；本次应扩充它，而不是依赖截图或人工目测作为唯一验证。
- 工作区当前已有与此前塔罗重设计相关的未提交文件。实现时只修改本规格列出的文件，保留其他用户改动。

## 视觉与动效语言

### 共同原则

1. 使用 `transform`、`opacity`、`filter` 和伪元素完成动画，避免驱动布局的 `top`、`left`、`width` 逐帧变化。
2. 每个阶段只保留一套最终关键帧；删除或覆盖旧关键帧时必须确保选择器优先级不会让旧规则重新生效。
3. 使用 `cubic-bezier` 的单向缓入/缓出，禁止左右来回的弹簧式切牌轨迹和高频抖动。
4. 对 `prefers-reduced-motion: reduce` 提供接近即时完成的替代：不循环、不闪烁，状态仍然可辨识。
5. 所有交互在动画播放期间锁定，动画完成由现有 `onAnimationEnd` 或状态回调确认，避免重复点击造成重复牌或错误阶段。

### B「紫雾回响」效果

- 主色：深靛紫背景、低饱和紫雾光晕、限制使用的旧金色边缘光。
- 紫雾使用低频 `opacity` + `scale` 呼吸，周期约 2.0–2.3 秒；不使用快速闪烁。
- 牌影使用低强度紫/金 `drop-shadow`，仅在牌离开牌堆的关键段出现，落位时衰减。
- 牌面保持统一牌背资源 `/tarot/ui/card-back.jpg`，不在动效中改变牌背内容。

## 洗牌动效

### 结构

保留十张牌的 `.tarot-shuffle-deck__slot` 与 `.tarot-shuffle-deck__card` 结构。十张牌分为左右两组（前五张与后五张）；牌堆中心保留可见的紫雾环和微弱金色星点。

### 时序

- 触摸/指针按下后循环播放，单循环约 2.15 秒；动画采用 `infinite alternate`，保证按住期间持续运动。
- 左右两组在约 40%–48% 时达到最大分离，水平位移约 60–72px，垂直抬升约 16–24px，允许 `translateZ(16–26px)` 表现层次。
- 约 70% 时两组以轻微交叉错位回到中心，随后平滑回到牌堆；不能出现瞬间跳回。
- 每张牌保留 0.08–0.16 秒的交错延迟，让十张牌像连续波纹而不是整体抖动。
- 松开、离开按钮或取消指针后停止循环，牌堆在不超过 240ms 内回到静止叠放。

### 反馈与边界

- 洗牌进度仍由现有 `shuffleProgress` 驱动；按住时间达到 100% 后按钮可进入切牌。
- 洗牌按钮必须继续支持 `pointerdown`、`pointerup`、`pointerleave`，并补充 `pointercancel` 清理定时器。
- 洗牌牌组在 320px 宽屏幕不横向溢出；最大运动区域由 `min(92vw, 360px)` 约束。

## 切牌动效

### 结构

保留 `.tarot-cut-deck__left` 作为可移动的上半叠、`.tarot-cut-deck__right` 作为承接的下半叠。两叠初始垂直重叠，使用 z-index 只表达谁在上，不通过左右分开制造“左边一下、右边一下”。

### 时序

- 点击牌堆开始一次约 0.90 秒的单向切牌。
- 未交换状态：上半叠先 `translateY(-36px)` 抬升，随后沿轻微弧线（横向不超过 4px）越过下半叠，最后 `translateY(8px)` 落到下方；下半叠只做 2–4px 的承接抬升。
- 已交换状态：使用镜像关键帧，让当前上层执行同样的上移—越过—下落；不要出现额外的左右来回。
- 关键阶段：0% 静止，28% 抬升，58% 越过最高点，82% 开始落位，100% 完成；轨迹连续，不在中间帧修改 z-index。
- 完成由 `onAnimationEnd={finishCut}` 触发，随后递增 `cutCount`，并将上下叠的静态层级反转，使“已经切过”在视觉上明确。

### 反馈与边界

- `cutting` 为 true 时禁用重复切牌和“完成切牌”按钮。
- `cutCount > 0` 后保留继续切牌能力；只有动画结束后才允许进入选牌。
- 切牌光晕使用一次性低频紫雾扩散，持续时间与主动画一致，不循环。

## 抽牌动效

### 结构

保留扇形牌 `.tarot-fan__card` 和内部 `.tarot-fan__visual`，在扇形底部增加明确的 `.tarot-fan__deck-anchor`（或等价伪元素）作为下方牌堆视觉锚点。已选牌继续渲染在 `.tarot-picked-row`，但必须使用更宽的间隔。

### 交互与时序

1. 用户点击一张未选牌后，设置 `flyingCard`，立即禁用所有其他扇形牌。
2. 被选牌从自身当前位置先向下回到牌堆中心锚点（短暂 80–120ms），再沿垂直上行轨迹离开底部牌堆，最后落入已选牌区域；视觉上必须能辨认“从下面抽上来”，不能只从扇形位置向上淡出。
3. 单张动画总时长约 0.55 秒：牌堆分离 0%–20%，上行 20%–78%，落位 78%–100%；落位时 scale 从 1.06 回到 1，紫色牌影衰减。
4. `onAnimationEnd` 调用 `finishPick(index)`，将索引加入 `picked` 并清空 `flyingCard`；在此之前不允许第二张开始飞行。
5. 三牌阵必须逐张完成：第一张落稳后用户再点第二张，第二张落稳后再点第三张。三张已选牌使用 `gap: clamp(18px, 6vw, 34px)`（窄屏可降至 14px），不能相互遮挡。
6. 已选牌区域保留序号徽章和入场 settle 动画；选过的扇形牌隐藏但不改变其他牌的几何位置，避免扇形跳动。

### 可访问性与边界

- 扇形按钮继续使用 `aria-label="第 N 张牌"`。
- 飞行期间按钮 `disabled`，并保留现有“已选 n / 总数”提示。
- reduced-motion 下跳过飞行路径，直接将牌加入已选区，但仍通过 `finishPick` 保证状态顺序。
- 三牌阵在 320px 宽度下不产生水平滚动；已选牌宽度与间距使用 `clamp`，不依赖固定像素总宽度。

## 文件边界

### 修改

- `src/games/tarot/TarotGame.tsx`：补充 `pointercancel`，增加抽牌底部牌堆锚点，确保逐张动画锁定和完成回调，必要时增加用于 CSS 轨迹的状态类。
- `src/styles.css`：清理塔罗仪式相关重复覆盖，收敛为洗牌、切牌、抽牌各一套最终关键帧；新增紫雾光环、抽牌底座、三牌间距和 reduced-motion 规则。

- 其他游戏、聊天和资源生成代码。

## 验收标准

- 洗牌长按时：牌的横向/纵向活动范围比当前明显更大；运动连续，没有抖动或突然跳位；紫雾呼吸和金色高光可见但不刺眼。
- 切牌点击后：能清楚看到上半叠从牌堆上方抬起、越过并落到下半叠；没有左移一下、右移一下的往返感；动画结束后上下层关系反转且按钮状态正确。
- 三张抽牌时：每次只飞一张；每张都从下方牌堆锚点向上移动；前一张结束前不能点下一张；三张最终间距明显且不重叠。
- 320px 及以上移动端宽度无横向溢出；`prefers-reduced-motion: reduce` 下无循环动效和快速闪烁。
- 现有塔罗单元测试、样式测试、TypeScript 构建和 Vite 构建全部通过。

## 测试策略

采用测试先行：先在 `tarotRitualStyles.test.ts` 写出上述行为的失败断言，确认失败原因是缺少新结构/关键帧，再最小化修改 TSX/CSS 使其通过。最终执行 `npm test -- --run`、`npm run build`，并在移动端窄宽度与 reduced-motion 条件下进行一次人工浏览器检查。
